# 威胁模型

更新：2026-10-26。以下描述本地源码中的保护和限制，不代表生产环境、双实体设备或独立密码学审计已通过。具体修复与验证证据见[安全治理记录](Privacy_Boundary_Governance_2026-10-22.md)；历史验收保留在原审查报告中。

## 资产、攻击者与信任边界

资产包括消息/附件正文及文件名、客户端私钥/对称密钥、账号与设备控制权、本地数据库及备份恢复材料。主要边界是已锁定/已解锁设备、Keychain/SwiftData/缓存、客户端/后端、后端/PostgreSQL/Redis/文件系统，以及独立保管的备份私钥。

攻击者可控制网络、取得数据库/对象存储/备份副本、使用被屏蔽或撤销的设备，或控制后端并向不同客户端返回不同目录。设备运行时/root、账号签署权或全部见证同时失陷不由 E2EE 或备份加密单独解决。服务器仍可观察必要元数据并阻断通信。

## 协议兼容与失败策略

- v1 是本地 Master Key 加密；v2 是本机模拟链、保留根密钥，不具备所宣称的前向保密；v3 仅保留受限历史读取，当前在线创建及控制事件只允许 v4；不自动降级。服务端旧 v3 写入及公钥查询/补充接口已移除，但数据库中的旧事件仍可能被投递。
- v3 未经端侧认证的远端删除/已读不改变本地状态；v3 编辑必须绑定 revision，旧协议不能修改 v4 消息。服务器送达提示只用于 v4 传输状态，不是端侧阅读证明。旧请求签名域 v1 不再接受；v2 设备签名不等于客户端二进制证明。
- 目录/身份/版本/认证失败停止相关发送和确认，保留恢复材料；不得接受新根、覆盖已固定身份或删除未决 journal 来消除错误。目录强制策略目前只是[迁移设计](Privacy_Boundary_Governance_2026-10-22.md#需要协议升级跨设备可信目录2026-10-23-补齐实施设计尚未实施)，未上线。
- 密钥透明性需要独立信任根、最新完整值及一致性证明、见证策略和新鲜度限制。全部见证串通、账号签署权失陷、初始信任错误及持续网络隔离不由日志单独解决。
