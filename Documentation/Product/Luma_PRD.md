# Luma 产品需求文档

## 定位与理念

Luma 是以 Apple 原生体验和本地优先为基础的一对一隐私聊天客户端。当前产品可在一台设备上注册本地账号、管理联系人并进行本地聊天；未来计划接入只转发密文的通信服务。安全表述必须与实际能力一致：当前本地加密不等于真实远端 E2EE。

设计原则：默认少暴露、敏感字段先加密再落盘、解锁后才读取内容、失败时明确提示、功能状态可被用户理解。服务器方案不得要求上传密码、私钥、Master Key 或 Session Key。

## 用户体系

**已实现**：本机唯一的 UserID、本地密码验证、可修改昵称和头像/简介；UserID 创建后没有常规修改入口。密码为带随机盐的 PBKDF2-SHA256 验证值，PIN 验证值在 Keychain；Face ID 仅作为本机门禁。允许通过 UserID 被搜索默认关闭，仅对同一设备的本地账号发现有效。

**未来计划**：全局唯一 UserID、设备授权登录、精确查找与防枚举。服务器认证方案见 [API 规格](../Backend/API_Specification.md)，不能把现有本机密码直接当作服务器凭据。

## 功能范围

| 能力 | 状态与边界 |
| --- | --- |
| 本地聊天 | **已实现**：文字与模拟附件、草稿、回复、编辑、删除、转发、收藏、Emoji 回应、置顶、未读数、已读设置；不代表远端送达。 |
| 好友 | **已实现**：本机账号搜索、联系人及加密备注；扫码/邀请等远端流程尚不可用。 |
| 隐私控制 | **已实现**：PIN/Face ID、聊天锁、隐私模式、消息预览与后台隐藏、截图/录屏本机检测开关；不能阻止截图或通知对方。 |
| 本地数据保护 | **已实现**：选定字段 AES-GCM、Keychain 密钥、加密搜索索引、密码加密备份；并非整库加密。 |
| 会话密码学 | **已实现的本机模拟**：身份/设备密钥、PreKey、会话根密钥与基础对称链；不提供真实远端 E2EE 或前向保密。 |
| 通信 | **设计中**：服务器认证、好友确认、密文转发、游标同步、WebSocket、APNs、多设备。 |

## 隐私原则与 UI

聊天采用 SwiftUI、系统导航、TabView、SF Symbols、系统蓝/灰消息气泡，兼容浅色/深色与 Dynamic Type。安全详情须明确区分“本地加密已开启”和“未连接服务器”；模拟在线/正在输入状态须标注模拟。隐私中心集中呈现可理解的设置，已读回执关闭时不得发送对外回执。

## 阶段规划

当前交付基线是本机可用客户端与网络抽象接口。下一阶段先完成独立的安全协议评审与服务端实现，再接入真实通信；真实 E2EE 需要经认证的设备密钥目录、预密钥握手、重放保护、密钥轮换和多设备策略。详见[路线图](Feature_Roadmap.md)。
