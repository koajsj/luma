# 功能路线图

此表按当前仓库可见实现记录，不以阶段名称推断完成度。状态随代码交付更新。

| 能力 | 状态 | 现有范围 / 下一道门槛 |
| --- | --- | --- |
| 本地聊天与消息状态 | **已实现** | SwiftData、本机回执、编辑/回复/回应等；无远端确认。 |
| 本地加密 | **已实现** | 消息、草稿、备注、部分偏好和索引加密；其他元数据仍可见。 |
| Identity Key、Device Key | **已实现** | P-256 本机密钥对，私钥在 Keychain；在线登记可上传公钥，目录可信验证尚未完成。 |
| Session 基础 | **已实现的本机模拟** | 静态 ECDH/HKDF、Keychain 会话根密钥；正式聊天仍用 v1。 |
| PreKey | **已实现的本机模拟** | 签名预密钥及一次性密钥池；旧 v2 不使用，v3 信封可混入一次性 ECDH。 |
| Ratchet 基础 | **已实现的本机模拟** | 每条 v2 消息有独立派生密钥；保留根密钥可重算，尚无前向保密。 |
| Sync 架构 | **已实现的接口与 Mock** | MessageEvent、Mock 同步仍保留；v3 `RemoteSyncCoordinator` 逐事件落盘和 ack 已在隔离后端与模拟器双账号验证。 |
| 加密备份 / 本地搜索 | **已实现** | 备份不含 Keychain 密钥和真实附件文件；搜索只在解锁后的本机进行。 |
| Go 后端、PostgreSQL、Redis、对象存储 | **已有基础工程** | 代码位于 `backend/`；已用本机隔离 PostgreSQL/Redis 与 iOS 模拟器验证文字链路，尚未部署。 |
| iOS 在线账号/好友接口 | **部分实现** | 设置页自愿登记设备、签名登录、资料和好友请求；聊天页可显式切换在线文字信封模式。 |
| WebSocket、APNs | **部分实现 / 未来计划** | iOS WebSocket 接口可收到提示；聊天页当前定时同步。APNs 仍只有后端预留接口。 |
| v3 逐设备消息信封 | **代码已实现，隔离联调通过** | 独立加密每设备的文字消息；模拟器双账号经本机 HTTPS 后端验证发送、接收、编辑、删除和回执。持久待发队列已实现，仍缺双实体设备验证与独立安全审计。 |
| 完整多设备与真实 E2EE | **未来计划** | 还需设备授权/撤销、透明密钥目录、完整 Ratchet、会话恢复及协议审计。 |

## 建议交付顺序

1. 冻结并评审 [威胁模型](../Security/Threat_Model.md)、[消息格式](../Protocol/Message_Format.md) 与密钥目录协议。
2. 实现后端认证和密文存储，建立多设备授权与撤销规则；先做端到端功能测试，不宣称 E2EE。
3. 交付经审查的真实 E2EE 协议，再切换正式聊天到 v2 或新版本。旧 v1 数据迁移与备份恢复必须单独验证。
4. 接入游标同步、WebSocket 提示、APNs、文件密文传输和多设备，并完成上线前安全审计。
